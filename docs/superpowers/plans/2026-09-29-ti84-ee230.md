# EE 230 calculator programs: implementation plan

> **For agentic workers:** each task below is self-contained. Its tests are already committed on the task's branch. Make them pass without editing them. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Build TI-84 Plus CE programs for EE 2300 that show the answer and then the work, generated from tested Python recipes.

**Architecture:** Python recipes (`src/ti84/recipes/`) → `gen.py` → TI-BASIC text → `tokens.py` (tivars) → `.8xp`. The same bytes are decoded and run by a Python interpreter of the TI-BASIC subset (`src/ti84/sim/`) in the tests. Read `docs/superpowers/specs/2026-09-29-ti84-ee230-design.md` first, then `docs/dialect.md`.

**Tech stack:** Python 3.12+, uv, tivars (the only runtime dependency), pytest.

## Global constraints

- Run everything through uv: `uv run pytest`, `uv run ti84-build`.
- No new dependencies. Only the standard library, tivars (only inside `src/ti84/tokens.py`) and pytest.
- Never edit a test to make it pass. If a test looks wrong, stop and report which test and why.
- Fail loud. No bare `except`, no swallowed errors, and no fallback that hides a wrong value. Every error names the program and line (sim) or the program/tool (model).
- The generated code and the helpers use only the dialect in `docs/dialect.md`, spelled exactly as its table shows (`Pause ` with a trailing space, `⁻` for negation, `ᴇ`, `𝑖`, `pi`).
- Screen text: 26 columns, rows 1–9 content, row 10 footer. Menu items ≤ 14 characters, prompts ≤ 13, titles and picture lines ≤ 26.
- Commits: short imperative subject, plain body saying what changed and why. No AI attribution or co-author lines. Commit on the task branch only; never push to `main`.
- Keep files focused. The sim is a package, not one giant file.

### Task 2: TI-BASIC interpreter (`src/ti84/sim/`)

**Files:**
- Create: `src/ti84/sim/__init__.py` (re-exports the public names below), plus modules split by job, e.g. `values.py` (numbers, lists, `toString`), `expr.py` (expression parser/evaluator), `program.py` (statement splitting, blocks, labels), `machine.py` (`Calculator`, run loop, screen, events).
- Tests (committed): `tests/sim/test_expr.py`, `tests/sim/test_programs.py`.

**Interfaces:**
- Consumes: `ti84.tokens.encode(text) -> bytes`, `ti84.tokens.decode(data) -> list[Token]` (`Token.bits: bytes`, `Token.text: str`, the display text), and `ti84.tokens.DIALECT: dict[bytes, str]`. Match tokens by `bits`, never by source spelling. The named-list prefix decodes as `ʟ`, π as `π`, `𝑖` as `𝑖`.
- Produces:

```python
class SimError(Exception): ...          # message is the TI error name or rule, then " at PROGRAM:LINE" when running a program

@dataclass(frozen=True) class Value:  x: object          # number, complex, list, or TI text like "10ᴇ⁻9"
@dataclass(frozen=True) class Key:    key: str | int     # "ENTER" (105), "CLEAR" (45), or a key code
@dataclass(frozen=True) class Hold:   key: str | int     # stays at the head; answers every Pause/getKey
@dataclass(frozen=True) class Choose: text: str          # picks a Menu( item by its text

@dataclass(frozen=True) class Out:       row: int; col: int; text: str
@dataclass(frozen=True) class Clear:     pass
@dataclass(frozen=True) class Wait:      key: str | int; screen: tuple[str, ...]   # 10 rows of 26 chars, before the key
@dataclass(frozen=True) class MenuShown: title: str; items: tuple[str, ...]; chosen: str | None
@dataclass(frozen=True) class Prompt:    prompt: str; typed: str

@dataclass
class Run:
    log: list            # Out | Clear | Wait | MenuShown | Prompt, in order
    screens: list[tuple[str, ...]]   # the screen at every Wait
    screen: list[str]    # final screen, 10 strings of exactly 26 chars
    prompts: list[str]
    menus: list[MenuShown]
    leaks: int
    steps: int
    stopped_at_menu: str | None

class Calculator:
    def __init__(self, complex_mode: bool = False, step_limit: int = 200_000): ...
    vars: dict[str, float | complex]      # "A".."Z", "θ"; reading a missing one gives 0.0, the dict stays sparse
    strings: dict[str, str]               # "Str0".."Str9"
    lists: dict[str, list]                # "L₁".."L₆", "⌊NAME"
    ans: object
    complex_mode: bool                    # set by the a+b𝑖 statement
    def load(self, name: str, data: bytes) -> None
    def load_text(self, name: str, text: str) -> None      # encode, then load
    def eval(self, text: str) -> object                    # one expression, against the current state
    def run(self, name: str, events=(), *, stop_at_menu: bool = False) -> Run
```

**Notes for the implementer:**
- Follow `docs/dialect.md` exactly: precedence, the implicit-multiplication rule and its `4𝑖` exception, leading `-`, closed parens and strings, lists, errors, the screen, script events and memory.
- Programs are token lists. Split them into statements at newline (3F) and at colon (3E) outside strings. Keep each statement's line number for errors.
- Blocks: keep a stack per program frame. `If c` followed by `Then` opens a block; when false, skip to the matching `Else` or `End`, counting nested `Then`/`For(`/`Repeat `. A single-line `If` (no `Then` next) guards only the next statement. `Goto` jumps to the first `Lbl` with that name from the top, and adds the number of open blocks it abandons to `run.leaks`.
- `For(v,a,b[,s])`: evaluate a, b and s once. Skip the body if `v` is already past `b`. `Repeat c`: the body runs, then `End` tests c and loops while it is false.
- Numbers: `float`, or `complex` when the imaginary part is nonzero. Normalize after every operation. Outside `complex_mode`, a complex result raises `ERR:NONREAL`.
- `round(x,n)`: `Decimal(repr(x)).quantize(Decimal(1).scaleb(-n), ROUND_HALF_UP)`. The calculator works in decimal, so `round(2.345,2)` must give 2.35.
- `toString(x)`: round to 10 significant digits with `Decimal` (`ROUND_HALF_UP`). Use plain notation when 1ᴇ⁻3 ≤ |x| < 1ᴇ10, otherwise `mantissaᴇexponent`. Drop trailing zeros and a trailing `.`, keep the leading `0` of `0.25`, and use `⁻` for negatives in both the number and the exponent.
- The screen is 10 × 26 cells. `Output(` wraps and truncates. `Input` writes `prompt + typed` at the cursor row and moves down, scrolling past row 10. `Menu(` shows up to 7 items (8 or more raises `ERR:ARGUMENT`).
- Events: `Pause` needs `Key("ENTER")` or a `Hold`. `getKey` pops a `Key` at the head, returns the `Hold` key, or returns 0. Each nonzero key logs a `Wait`. `Input` needs a `Value`. `Menu(` needs a `Choose`; with `stop_at_menu=True` and no `Choose` left (queue empty or a `Hold` at the head), the run ends cleanly with `stopped_at_menu` set. Leftover events other than a `Hold` raise `SimError("unused events: ...")`. A missing needed event raises `SimError("no event for Input ...")`, and a wrong-type event raises `SimError` naming the statement.
- The step limit counts executed statements, including loop passes.

### Task 3: Recipe model and generator (`src/ti84/model.py`, `src/ti84/gen.py`)

**Files:**
- Create: `src/ti84/model.py`, `src/ti84/gen.py`
- Tests (committed): `tests/gen/conftest.py`, `tests/gen/test_model.py`, `tests/gen/test_gen.py`

**Interfaces:**
- Consumes: `ti84.tokens.encode`, `decode`, `lint(text, program)` (raises `LintError`), `display_problems(text) -> list[str]`.
- Produces:

```python
# model.py
Kind = Literal["real", "complex", "list"]
Fmt = Literal["si", "fix2", "cplx"]           # helper: si→ZF, fix2→ZR, cplx→ZC

class ModelError(ValueError): ...             # every problem, one per line, "<PROGRAM>/<tool id>: <message>"

@dataclass(frozen=True) class Input:   var: str; prompt: str; kind: Kind = "real"
@dataclass(frozen=True) class Calc:    var: str; name: str; formula: str; expr: str; unit: str = ""; fmt: Fmt = "si"; sub: bool = True
@dataclass(frozen=True) class Poly:    var: str; name: str; formula: str; coeffs: str; at: str; loop: str; unit: str = ""; fmt: Fmt = "cplx"
@dataclass(frozen=True) class Note:    text: str
@dataclass(frozen=True) class Case:    cond: str; text: str
@dataclass(frozen=True) class Verdict: var: str; name: str; cases: tuple[Case, ...]; otherwise: str
@dataclass(frozen=True) class Guard:   cond: str; message: tuple[str, ...]
@dataclass(frozen=True) class Raw:     writes: tuple[str, ...]; compute: tuple[str, ...] = (); answers: tuple[str, ...] = (); work: tuple[str, ...] = ()
Step = Calc | Poly | Note | Verdict | Guard | Raw
@dataclass(frozen=True) class Tool:  id: str; label: str; title: str; picture: tuple[str, ...]; inputs: tuple[Input, ...]; steps: tuple[Step, ...]; answers: tuple[str, ...]
@dataclass(frozen=True) class Topic: program: str; title: str; tools: tuple[Tool, ...]

def validate(topic: Topic) -> None

# gen.py
def gen_topic(topic: Topic) -> str           # calls validate first
def gen_main(topics: Sequence[Topic]) -> str  # the EE230 program
def pieces(expr: str) -> list[tuple[str, str]]   # ("text", display text) | ("var", "A".."Z")
```

**Validation rules** (`tests/gen/test_model.py` is the full list): the program name matches `[A-Z][A-Z0-9]{0,7}`; the topic title is ≤ 14; tool ids are unique and there are ≤ 24 tools; the label is ≤ 14, the title ≤ 26, the picture ≤ 8 lines of ≤ 26; a tool has ≥ 1 input and ≥ 1 answer; prompts are ≤ 13. Input variables are `A`–`Z` (real or complex), or `L₁`–`L₆` with `kind="list"`. Calc and Poly variables are `A`–`Z`; Verdict variables are `Str1`–`Str7`. No variable is stored twice across inputs, steps and `Raw.writes`. Step names are unique, and answers name a Calc, Poly or Verdict. The reserved names `θ` `Str0` `Str8` `Str9` `⌊` never appear in any variable or code. Every expression and condition passes `lint`. A Calc with `sub=True` has no list in its expression. A Poly loop variable is not otherwise used, and its coefficients are `L₁`–`L₆`. A Verdict has ≥ 1 case. A Guard has 1–3 message lines of ≤ 26. Every display string (title, picture, prompt, names, formulas, units, notes, verdict texts, guard lines) has no `display_problems`.

**Generation** is fully specified by `EXPECTED_TOPIC` in `tests/gen/test_gen.py`:
- **Labels.** Tool *i* gets the *i*-th letter of `ABCDEFGHIJKLNOPRSTUVWXYZ` (no M or Q). Guard *k* of that tool is `<letter><k>`. Menu pages are `M`, `M1`, `M2`…, with 6 tools per page followed by `MORE` when more remain; the last page ends with `BACK`→`Q`.
- **Numbers lines.** `pieces` tokenizes the expression with `decode(encode(expr))`. Uppercase single-letter tokens become `("var", letter)`. Every other token becomes display text through this map, with neighbours merged: `π→PI`, `√(→SQRT(`, `𝑖→j`, `⁻→-`, `𝑒→e`, `𝑒^(→e^(`, `abs(→ABS(`, `ln(→LN(`, `log(→LOG(`, `int(→INT(`, `round(→ROUND(`, `min(→MIN(`, `max(→MAX(`, `real(→REAL(`, `imag(→IMAG(`, `angle(→ANGLE(`, `conj(→CONJ(`, `sin(→SIN(`, `cos(→COS(`, `tan⁻¹(→ATAN(`, ` and →AND`, ` or →OR`, `not(→NOT(`, `⁻¹→^-1`; anything else uses the token text as is.
- A Calc prints its numbers line only when `sub` is true and `pieces` contains a variable.
- The generated text ends with a newline, and every line is one statement.

### Task 5: Build and harness (coordinator)

`build.programs() -> dict[str, str]` returns `EE230`, every topic program and every helper. `build.build(out: Path) -> list[Path]` lints each program and writes `out/<NAME>.8xp` and `out/src/<NAME>.txt`. `main()` is the `ti84-build` CLI; it exits 1 and prints the lint or model errors.

`harness.run_tool(tool_id, inputs) -> ToolRun` builds every program in memory, runs `EE230` with `Choose` events down to the tool (through `MORE` pages), `Key("ENTER")` for the picture, a `Value` per input, then `Hold("ENTER")` with `stop_at_menu=True`. An input is a number, TI text such as `"3+4𝑖"`, or a list; a list holding any text is passed as TI list text (`{⁻1+2𝑖,⁻1-2𝑖}`). `ToolRun` has:

- `answers: list[str]`: the lines printed at column 1 between the inputs and the `ENTER:WORK  CLEAR:QUIT` footer, title first;
- `work: list[str]`: the lines after that footer, up to `DONE  ENTER:MENU`;
- `stopped: list[str]`: the message lines when a Guard stopped the tool (answers and work are then empty);
- `value(name)`: the final value of the Calc, Poly or Verdict step with that name;
- `calc` and `run`.

It is tested end to end with the `vdiv` example from the spec. The tool tests for Tasks 6 and 7 use exactly this interface.
